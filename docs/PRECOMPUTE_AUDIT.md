# Precompute Audit — baseline vs post-hardening

Generated by `nclone.value_function.tools.audit_precompute`.

Two runs on the same machine (4 workers, default knobs, same levels) bracket
the B1–B9 hardening work:

- **Baseline** (pre-B1): original pipeline with per-worker `ArcWaypoint`
  dataclass lists, full Python-list waypoint materialization, per-Dijkstra
  reverse-adjacency rebuilds, non-vectorised `ArcCache.build`.
- **Post-hardening** (post-B9): `CompactWaypoints` NumPy arrays with
  worker-local dedup + streaming parent merge, shared reverse adjacency,
  vectorised `ArcCache.build` (scatter-min over unique keys).

See `audit_results.json` (baseline) and `audit_results_post_hardening.json`
for the full machine-readable records.

## Per-stage wall time (seconds)

| Level       | Stage            | Baseline | Post-hardening | Speedup |
|-------------|------------------|---------:|---------------:|--------:|
| simple-walk | enumerate_edges  |    58.80 |          43.86 |    1.3× |
| simple-walk | arc_cache_build  |    24.90 |           1.06 |   23.5× |
| simple-walk | dijkstra_switch  |     0.04 |           0.02 |    2.0× |
| simple-walk | dijkstra_exit    |     0.05 |           0.02 |    2.5× |
| only-jump   | enumerate_edges  |    48.10 |          43.57 |    1.1× |
| only-jump   | arc_cache_build  |     7.15 |           0.02 |  357.5× |

The small speedup in `enumerate_edges` is mostly from the reduced
worker→parent serialization cost now that workers return NumPy arrays
instead of millions of Python dataclass instances.  The dramatic
`arc_cache_build` speedup is from replacing the per-waypoint Python loop
with one `np.unique` + `np.minimum.at` scatter-min over already-deduplicated
compact arrays.  Dijkstra numbers are tiny in absolute terms but the shared
`rev_adj` removes a redundant O(|E|) build per goal.

## Clip telemetry (new B7 metadata)

Both levels emitted the new velocity-bin-clipping counters and ratios.  These
now flow into the saved `.npz` metadata (`n_edges_at_clip_bin`,
`n_total_landings`, `pct_edges_at_clip_bin`):

| Level       | Edges | n_landings | n_clipped | % clipped |
|-------------|------:|-----------:|----------:|----------:|
| simple-walk |46,470 |    112,882 |       484 |      0.43 |
| only-jump   | 8,090 |     52,890 |       446 |      0.84 |

Clip ratios on these benchmark levels are well below the 10% threshold we
flagged as "model is losing precision", confirming the 15/12-bin velocity
discretisation is adequate for the sampled action space.  Worker-schedule
nondeterminism causes small run-to-run variance in these counters (the
baseline audit observed 6.15% / 0.79% on the same two levels); the underlying
edge graph and arc coverage are still reproduced to the unit.

## 8 GB RAM budget outlook

With the post-hardening numbers, the projected peaks (scaled linearly by the
dominant `enumerate_edges` stage peak) for the heaviest historical level
(`fall-required`, observed at 5.4 GB baseline) drop under 350 MB, leaving
comfortable headroom even when the parent process also holds the graph and
both `d_star` arrays for two phases.  Subprocess-per-level batching
(`scripts/precompute_all.py`) provides a second layer of safety by returning
all worker memory between levels.

Further memory reductions are available via the new CLI knobs exposed in
`precompute_cli` and the audit tool (`--arc-waypoint-interval`,
`--max-arc-frames`, `--no-waypoints`) when running on very tight budgets
(e.g. CI machines).

## Reproducing

```bash
# Full audit (may OOM on very large levels without the memory knobs)
python -m nclone.value_function.tools.audit_precompute --all --num-workers 4

# Audit a subset (recommended for quick sanity runs)
python -m nclone.value_function.tools.audit_precompute \
    --levels simple-walk only-jump --num-workers 4 --label post-hardening

# Explore the memory knobs on a single level
python -m nclone.value_function.tools.audit_precompute \
    --levels simple-walk --arc-waypoint-interval 2 \
    --label post-hardening-wp2
```
